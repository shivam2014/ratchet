How Ratchet actually runs

Ratchet is a referee. In v0 it never reads the prompt, plans the task, or writes code. It gates tool calls and runs checks.

v0 diagram: manual contract. The target flow adds a prompt router and a stop gate. Ratchet reads the prompt locally to choose a contract profile and a skill shortlist, then runs the checks before the model can finish. See vision.md and routing.md. The statements below about Ratchet not seeing the prompt describe v0.

Where Bend sits

Bend is a language whose compiler can check proofs. In the green box above it is one command: bend PROOF.bend --check-only.

Ratchet is not written in Bend and does not require it. --bend is only a preset that adds two things to a normal contract: a gate on LAWS.bend and the Bend command to verify. A TypeScript/JS Flappy repo gets lint, tests, arch, and tamper; Bend would not verify that code.

Use Bend for a core you are willing to model in Bend. The law is the human-owned spec; the proof is the agent's obligation; Ratchet runs the checker and records the verdict.

Why flags exist

--pstack and --bend are presets, not the architecture. They write standard contract fields:

gates = artifacts that must exist before a pattern is writable.
verify = commands that must exit 0 before done.

You can skip every flag and put the same two fields in .ratchet/config.json. The flags just save typing and keep the messages consistent. If they feel like feature creep, config-only is the cleaner surface.
